## 2. Vulnerability Description

A Stored Cross-Site Scripting (Stored XSS) vulnerability was identified in the administrative component responsible for managing geographic zones in Modified Shop.

The vulnerability is related to the presentation of database-persisted data without evidence of contextual HTML encoding at the output points identified in `admin/zones.php`.

The affected fields are:

- `zone_name`
- `zone_code`
- `countries_name`

Stored content may be interpreted by the browser as HTML or JavaScript when displayed in the administrative interface, if no additional protection is applied at the rendering layer.

## 3. Affected Endpoint

```http

```

## 5. Technical Evidence

### 5.1. Data Persistence

File: `admin/zones.php`

**Line 35 - Insertion:**

```php
xtc_db_query("insert into " . TABLE_ZONES . " (zone_country_id, zone_code, zone_name) values ('" . (int)$zone_country_id . "', '" . xtc_db_input($zone_code) . "', '" . xtc_db_input($zone_name) . "')");
```

**Line 44 - Update:**

```php
xtc_db_query("update " . TABLE_ZONES . " set zone_country_id = '" . (int)$zone_country_id . "', zone_code = '" . xtc_db_input($zone_code) . "', zone_name = '" . xtc_db_input($zone_name) . "' where zone_id = '" . (int)$zone_id . "'");
```

The data is persisted using `xtc_db_input()`, a mechanism related to preparing values for SQL queries.

This protection does not replace the contextual encoding required when rendering the values as HTML.

### 5.2. Rendering in the Zone List

**Lines 112-114:**

```php
<td class="dataTableContent"><?php echo $zones['countries_name']; ?></td>
<td class="dataTableContent"><?php echo $zones['zone_name']; ?></td>
<td class="dataTableContent txta-c"><?php echo $zones['zone_code']; ?></td>
```

The three values are written directly to the HTML output without explicit escaping in this section.

### 5.3. Rendering in the Edit Form

**Lines 152-153:**

```php
xtc_draw_input_field('zone_name', $cInfo->zone_name)
xtc_draw_input_field('zone_code', $cInfo->zone_code)
```

Persisted values are passed to the helpers responsible for generating the HTML fields.

The effective security of these points also depends on the internal implementation of `xtc_draw_input_field()`.

### 5.4. Rendering in the Deletion Confirmation

**Line 162:**

```php
$contents[] = array('text' => '<br /><b>' . $cInfo->zone_name . '</b>');
```

The zone name is directly concatenated into HTML content.

### 5.5. Rendering in the Information Panel

**Lines 167-171:**

```php
$heading[] = array('text' => '<b>' . $cInfo->zone_name . '</b>');

$contents[] = array('text' => '<br />' . TEXT_INFO_ZONES_NAME . '<br />' . $cInfo->zone_name . ' (' . $cInfo->zone_code . ')');

$contents[] = array('text' => '<br />' . TEXT_INFO_COUNTRY_NAME . ' ' . $cInfo->countries_name);
```

The values are directly concatenated into the HTML content generated by the administrative component.

### 5.6. Proof of Concept

The following benign payload was used in the laboratory:

```html
<img src=x onerror=alert('XSS-STORAGE-DOUGLAS')>
```

After storing the value and loading the affected administrative page, the browser executes the injected JavaScript code.

## 6. Impact

Exploitation of the Stored XSS vulnerability may allow:

- JavaScript execution in the browsers of users who view the affected content;
- Manipulation of the administrative interface;
- Execution of actions on behalf of authenticated users, depending on their permissions and existing protections;
- Compromise of administrative session integrity in scenarios where security controls permit it.

Exploitation depends on the ability to write the data and on another user viewing the affected record.

## 8. Remediation Recommendation

It is recommended to:

1. Apply contextual HTML escaping to all dynamic values displayed in the administrative interface;
2. Ensure that helpers responsible for generating HTML fields properly encode attribute values;
3. Use mechanisms such as `htmlspecialchars()` with `ENT_QUOTES` and UTF-8 encoding, according to the output context;
4. Validate received data according to the expected format of each field;
5. Review all rendering points for persisted data, including administrative panels and confirmation messages;
6. Implement a Content Security Policy as an additional security control;
7. Implement CSRF protection for administrative operations.

Example remediation:

```php
echo htmlspecialchars(
    $zones['zone_name'],
    ENT_QUOTES | ENT_SUBSTITUTE,
    'UTF-8'
);

echo htmlspecialchars(
    $zones['zone_code'],
    ENT_QUOTES | ENT_SUBSTITUTE,
    'UTF-8'
);
```

Input validation should complement, not replace, output encoding.
